## Correcciones incluidas

- Los enlaces de profesionales y centros ahora aplican el filtro. Hay filtros combinables por área, modalidad, verificación y zona; búsqueda con tildes y términos como «psicólogo TOC».
- Portada con buscador inmediato, categorías, perfiles y explicación breve; navegación adaptable, enlace para saltar al contenido, foco visible y favicon propio.
- Los cuatro perfiles del seed original son ficticios. Una migración los identifica expresamente y retira la verificación. El seed exige `DEMO_DATA=1`; no deben usarse esos perfiles como recomendaciones reales.
- Los datos públicos de ratings se calculan a partir de reseñas publicadas, no de cifras prefabricadas. Publicar u ocultar una reseña cambia inmediatamente el resultado. No se muestra un promedio con menos de seis reseñas; seis no garantiza representatividad.
- Aprobar una propuesta crea el perfil y lo vincula con la propuesta dentro de una transacción. Repetir la aprobación no duplica el perfil. La publicación nunca concede una verificación sin evidencia.
- Se pueden reportar reseñas publicadas; los reportes llegan al panel existente y no eliminan automáticamente las críticas. Reportes abiertos duplicados de la misma persona son idempotentes.
- La publicación anónima usa «Paciente anónimo», sin un seudónimo persistente que permita correlacionar consultas.
- Validación de meses, longitud de comentarios, límites de registro y direcciones web; cookies malformadas no generan error 500.
- Las escrituras verifican el origen del formulario. HTML con `no-store`, política CSP y restricciones de enmarcado. La ruta se puede probar sin iniciar un servidor.

## Ejecución

Requiere Node 22.5 o posterior (probado con Node 24). No necesita dependencias externas.

```bash
npm run db:migrate
npm start
```

Las variables de `.env.example` son una referencia: el servidor toma variables del entorno, no carga `.env` automáticamente. Para usar un archivo `.env` en Node compatible:

```bash
node --env-file=.env src/server.js
```

Detrás de un proxy HTTPS, configurar `APP_ORIGIN` con el origen público exacto y `NODE_ENV=production`. Mantener `DATABASE_PATH` en un volumen persistente con backups. Antes de ejecutar nuevas migraciones en una instalación existente, respaldar su base.

Para una demostración aislada (no contiene profesionales verificados):

```bash
DEMO_DATA=1 DATABASE_PATH=data/demo.db npm run db:seed
DATABASE_PATH=data/demo.db npm start
```

## Publicación con Sites

La aplicación existente depende de `node:http`, `node:sqlite` y archivos persistentes. Sites publica Workers de Cloudflare y ofrece D1; no ejecuta directamente este servidor con su archivo SQLite. Hace falta una adaptación explícita del servidor y la capa de datos para publicar la aplicación funcional en Sites. No se sustituyó la aplicación por una maqueta estática ni se creó un sitio duplicado.


### Actualización: adaptación terminada

Se agregó el servidor compatible con Sites y D1, conservando también el arranque Node local. Doce pruebas cubren ambos caminos, registro, moderación y compatibilidad de hashes existentes. Las pruebas de D1 usan una implementación asíncrona de su interfaz sobre SQLite y no sustituyen la verificación de publicación. WebMCP incorpora únicamente navegación a la búsqueda; no se contó con un contexto de navegador autorizado para comprobar su registro.

Para desarrollo, ejecutar `npm ci` antes de los comandos de Node; ahora hay dependencias declaradas. `npm run build` prepara la publicación en Sites. La base publicada comienza vacía y las propuestas requieren moderación. La verificación profesional documentada, las respuestas y otras fases pendientes siguen sin implementarse.
